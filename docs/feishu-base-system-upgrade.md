# 把多维表格做成「像系统一样」：能力实测 + 已落地改造

> 状态：**已在你的 Base「智能客服运营跟踪」上实施（2026-09-12）**。全部为新增（加列/加视图/关联升级），
> 未改动你已有列的数据；探测用的临时表已全部删除。

## 0. 一句话结论

「按钮」飞书没有开放创建 API，**必须你在表格里手动加（约 10 秒/个）**；
其余「系统感」组件——自动编号、公式、人员、多选、双向关联、看板/画册/表单/筛选视图——**我已通过 API 直接建好**；
仪表盘同样只能手动建（创建接口 404，只读得到）。

## 1. 能力实测（真实凭证，逐项验证）

### 1.1 字段：能建的 / 建不了的

| 结论 | 字段类型 |
| --- | --- |
| ✅ 可建 | 文本(1)、数字(2)、单选(3)、多选(4)、日期(5)、复选框(7)、**人员(11)**、电话(13)、超链接(15)、**附件(17)**、单向关联(18)、**公式(20)**、**双向关联(21)**、地理位置(22)、群组(23)、创建时间(1001)、修改时间(1002)、创建人(1003)、修改人(1004)、**自动编号(1005)** |
| ❌ 不可建 | **按钮(3001)**、查找引用(19)、以及数字的「进度/货币/评分」变体（formatter 只接受 `0`、`0.00` 这类数值格式） |

报错原文（`查找引用` 那次把白名单直接吐出来了）：
`type is optional, options: [1,2,3,4,5,7,11,13,15,17,18,20,21,22,23,1001,1002,1003,1004,1005]`。

### 1.2 视图：能建的 / 建不了的

| 结论 | 视图 |
| --- | --- |
| ✅ 可建 | 表格(grid)、**看板(kanban，需指定分组字段)**、**画册(gallery)**、**表单(form)**；表格/看板视图可带**筛选**(`filter_info`)与**分组**(`group_info`) |
| ❌ 不可建 | 日历(calendar)这套参数不被接受 |
| ❌ 不可建 | **仪表盘**(`POST /dashboards` 404；`GET` 可读但建不了) |

### 1.3 两个必须记住的坑

1. **日期列的秒级格式 API 设不了**：`date_formatter` 只接受 `yyyy/MM/dd HH:mm` 与 `yyyy-MM-dd HH:mm`；
   传带秒的会报 `1254084 DateFieldPropertyError`。秒只能在飞书界面里点（这也解释了新建列默认「只有日期」）。
2. **公式里日期相减的单位是「天」，不是毫秒**（实测：`NOW()-首现时间` 对 25 小时前 = 1.0417）。
   所以「按毫秒写」的 `(NOW()-首现时间)/3600000` 会算成 0.0000003、`> 86400000` 永远为假。
   正确写法：小时 = `(NOW()-首现时间)*24`；超 24h 判断 = `NOW()-首现时间>1`。
   （`DATETIME_DIFF(...,"h")` 在这个 Base 里没算出值，先不用它。）

## 3. 只能你在飞书界面点的四件事（附步骤）

### 3.1 按钮列（重点：这是唯一能「点一下就干活」的组件）

在「数据表」里 **+ 添加字段 → 类型选「按钮」**，建议三个：

| 按钮名 | 动作 | 配置要点 |
| --- | --- | --- |
| 认领 | 更新记录 | 把「跟进人」设为「当前用户」、把「状态」设为「跟进中」 |
| 已解决 | 更新记录 | 把「状态」设为「已解决」 |
| 复制跟进要点 | 打开链接 / 复制 | 或改成「发送消息」把该行发到运营群 |

> 关键联动：**同事在飞书点按钮改的状态/跟进人，会被客户端每 2 分钟拉回本地**（回写闸门早已实现），
> 所以「在飞书点一下」= 本地议题也跟着处理了，不用两头维护。

### 3.2 日期格式补秒

点列头 → 日期格式 → 选带秒的那项（API 只能到分钟）。建议只给「首现时间 / 最近更新 / 时间」三列设。

### 3.3 自动化（3 条就够用）

1. **超时提醒**：触发=记录满足条件（状态=待处理 且 超时预警 包含「超」）→ 动作=发送飞书消息给「跟进人」（没人就发运营群）；
2. **新问题通知**：触发=新增记录 → 动作=发卡片到运营群（标题 + 客户群 + 工单号）；
3. **闭环回执**：触发=状态 变为 已解决 → 动作=发消息 + 更新「处理备注」。

### 3.4 仪表盘

新建仪表盘，放三张图：新增 vs 解决趋势（按首现时间/最近更新）、按类型分布（饼图）、按客户群 Top10（条形）。

## 6. 应用侧落地（2026-09-12 第二轮：可复用的「一键升级」+ 人员列）

### 6.1 一键升级表格（设置页按钮）

- 位置：设置 → AI 助手 → 议题同步卡片 →「高级信息」里的 **表格系统化（工单号 / 超时预警 / 看板 / 表单）**；
- 行为：`src/main/services/lark/baseSystem.ts` 的 `upgradeBaseToSystem()` —— 建 4 列（工单号/等待时长/超时预警/标签）、
  建 4 个视图（看板·按状态 / 待处理 / 超时未处理 / 新增问题表单）、把证据表「关联议题」升成双向、
  给回复表建看板视图；**全部幂等**（按名字先查再建，重复点只显示「已存在」）；
- 结果按「＋ 新建 / · 已存在 / ⚠ 失败」逐条列出，并附「只能手动点」的清单（可一键复制）；
- 实测：在已经手工升级过的 Base 上再跑一次，12 步全部 `skipped:已存在`，没有重复造列。

### 6.2 处理人（飞书人员列）

- 开关：同一处「处理人（飞书成员）」；打开后升级会建出人员列（默认列名 `处理人`，可改）；
- 映射：`称呼 → open_id`。两条来源——① 自动：读应用可见的通讯录（`refreshPersonMap()`，结果缓存 24h）；
  ② 手工：设置页可直接写「陈西西=ou_xxx」，**手工优先**，通讯录读不到姓名时靠它；
- 写入：同步议题时若有跟进人且能映射到 open_id，就写 `[{id: open_id}]`；**映射不到就留空**（写空数组会清掉同事在飞书选的人）；
- 实测：写入格式验证通过（写进去后读回是飞书成员「江特捷」）；
- **前提**：本租户目前只能看到 1 个人且读不到姓名 → 需要在开放平台补 `contact:user.base:readonly` 并把
  「权限管理 → 数据权限 → 通讯录可见范围」设为全部员工或指定部门；否则请用上面的手工映射。

### 6.3 能力边界的完整结论（SDK 资源层实测）

| 资源 | 可用方法 | 结论 |
| --- | --- | --- |
| `bitable.v1.appTable` / `appTableField` / `appTableRecord` / `appTableView` | 建/查/改 | ✅ 列、记录、视图都能程序化 |
| `bitable.v1.appTableForm` | `get` / `patch` | 表单可读取与改配置（描述、字段） |
| `bitable.v1.appDashboard` | 只有 `copy` / `list` | ❌ **不能新建仪表盘**（只能复制现有或列出） |
| `bitable.v1.appWorkflow` | 只有 `update` / `list` | ❌ 不能新建自动化，但**可以列出与启停**：建好后应用可代为开关 |
| `bitable.v1.appRole` / `appRoleMember` | 建/改/删/查 | ✅ 角色权限可程序化（例如「只读给全公司、编辑给客服组」） |
| `bitable.v1.appTableFieldGroup` | `create` | ✅ 字段分组可建 |
| 按钮字段 (3001) | —— | ❌ 字段类型白名单里没有，只能在界面加 |
