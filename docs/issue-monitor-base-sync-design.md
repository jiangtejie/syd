# 问题监控列表 ↔ 飞书多维表格同步:现状诊断与设计

> 状态:**设计稿(2026-09-12)**。基于对现有实现的代码审读 + 运行态实测 + 目标表真实结构。

## 0. 一句话结论

同步功能**早已实现且相当完整**(2026-09-11 三个提交:M1 单向 / M2 回写 / 影子记录),但它**从未被配置**
(运行态所有 lark.* 配置键为空);更关键的是:现有流程只认「按名字新建一张『议题』表」,而你给的是一张**已存在的表**
—— 于是即使配置跑起来,数据也进不了你正打开的那张表。

## 2. 为什么「看起来完全没同步」

1. **配置没做过**:没粘链接、没点过「验证并建表」、开关关着 → 调度器每轮在 lark.sync.enabled=false 直接返回(除日志外无任何提示);
2. **方向预期不一致**:现有 verifyBaseLink() 用链接里的 app_token,但**忽略链接里的 table=…**,而是按名字找/建「议题」表 → 你的「数据表」永远是空的;
3. 即使跑起来,问题监控页**看不到同步状态**(状态只在设置页与日志里),进一步加深「没同步」的印象。

## 3. 设计(复用现有引擎,只补「目标表」这一环)

### 3.1 目标表选择(核心改动,约 1 处函数)

- 链接**带 table=…** → 该表即「议题表」,**不新建**;链接不带 → 保持现状(新建「议题」)。
- 复用 parseLarkRef() —— **它已经解析出 tableId**(现有代码只是没用);verifyBaseLink 里改成:
  目标议题表 = parsed.ref.tableId ?? ensureTable(appToken, 议题, ISSUE_FIELDS)。
- 「数字员工回复」表维持「按名新建/复用」(它没有用户既有表可复用)。

### 3.2 字段补齐(把 ensureTable 拆出 ensureFields)

现在「补字段」逻辑耦合在 ensureTable 里(先找/建表,再列字段逐个补)。抽出 ensureFields(appToken, tableId, specs) 后两条路径共用:
- 你那张表:补 11 列(议题ID/客户群/类型/严重度/标题/摘要/状态/跟进人/处理备注/首现时间/最近更新/证据条数 —— 去掉已存在的);
- 单选列带 options(现有 fieldPayload 已支持),避免写入报错;
- **同名但类型不符**要报出来(现在只按名字跳过 → 会静默写入失败),列入自检输出。

### 3.3 主字段(你表里那个「文本」列)

飞书数据表第一列是主字段,**不可删除、类型不可改**。设计:
- 保留「文本」列不动(不重命名、不删除);
- 识别 index === 0 的字段,同步时**额外把「标题」写进主字段**(同事在手机上第一眼看到的就是问题标题);
- 若主字段恰好叫「标题」→ 正常按列名写入即可。

### 3.4 幂等与「认领既有行」

- 继续用 lark_sync_map(kind, local_id) → record_id 做 upsert(已实现);
- 新增**认领**:目标表已有历史行时,按「议题ID」列匹配本地 id 建立映射,否则同一议题会被**重复插入**;
- 认领只在首次配置/切换目标表时跑一次。

### 3.5 回写边界(保持现状 + 自检)

- 只在目标表存在 状态/跟进人/处理备注 三列时启用回写(collabOf 已按列名取值);补列后天然具备 → 双向同步开箱可用;
- 若用户删掉某列,回写自动退化(现有逻辑已容错)。

### 3.6 可观测(把「没同步」变成可自诊断)

| 位置 | 增加 |
| --- | --- |
| 问题监控页 | 顶部同步徽标(已同步 / 待同步 N / 失败:原因)+「立即同步」按钮(不必再去设置页) |
| 设置页验证流程 | 改为**预览式向导**:粘贴链接 → 展示「将写入:表『数据表』(现有 1 列,将新建 11 列)、回写列:是」→ 一键执行 → **试同步最近 5 条** → 展示逐条结果 |
| 失败原因 | 权限 / 协作者 / 限流 / 字段缺失 → 直接回显可行动文案(现在多数只落日志) |
| 同步记录 | 保留最近 N 轮结果(现在只有 lastResult 一个字符串) |

### 3.7 分阶段

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| **P0** | 指定表作为议题表 + 抽 ensureFields + 主字段写标题 + 验证流程预览与试同步 | 半天 |
| **P1** | 认领既有行 + 监控页同步状态与按钮 + 失败原因直显 + 最近同步记录 | 半天 |
| **P2(可选)** | 列名自由映射(你的表列名与标准列不同名时,向导里下拉映射) | 1 天 |

## 4. 风险

| 风险 | 缓解 |
| --- | --- |
| 往你既有表补列会**改表结构** | 只增不改不删;执行前预览「将新建哪些列」;可随时在飞书里手动删除 |
| 主字段不可改 | 保留原列,只写值(见 3.3) |
| 单选列选项缺失导致写入失败 | 补列时带上 options(已实现) |
| 限流 | 已实现:批量 100/批 + 120ms 间隔 + 串行 |
| 重复插入 | lark_sync_map + 3.4 认领 |
| 敏感信息外发 | 默认只推标题/摘要/群名;证据原文需显式打开开关并二次确认 |

## 5. 现在就能用的临时路径(零代码)

设置 → 议题同步到多维表格(飞书 Base) → 粘贴你给的链接 →「验证并建表」→ 打开同步开关。

**副作用**:会在该 Base 里**新建「议题」与「数字员工回复」两张表**,数据进这两张新表;你原来的「数据表」仍是空的。
若你能接受「多两张表」,今天就能看到同步效果;若你要的就是**写进自己那张「数据表」**,需要上面的 P0 改动。

> 该临时路径已被 §6 的实现取代:现在粘贴带 table= 的链接会**直接写进你指定的表**。

## 8. 界面收敛(2026-09-12 第三轮:标识隐藏 + 状态胶囊 + 高级折叠)

### 8.1 为什么改

前两轮把功能做全了,但界面是「把后端字段念给用户听」:一长串口语状态行、一眼看不到重点的标识

这一轮按「用户不关心标识,只关心『通没通 / 推了多少 / 要不要开』」重排。
