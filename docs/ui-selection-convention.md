# 列表 / 详情联动的选中规则（问题监控等主从界面）

> 状态：**已落地（2026-09-12）**。起因：问题监控里处置完一条问题后，不会自动选中下一条，右侧详情也不更新。

## 1. 症状与根因

**症状**：在「待处理」列表里点「已解决/归档」后，那条问题从列表消失，但右侧详情仍然挂着它 ——
既不切到下一条最前面的问题，状态还显示成旧值。

**根因有两个，都是「选中项没有跟着列表走」**：

1. `MonitorPage` 的默认选中 effect 是这么写的：`if (active || loading || statusFilter !== 'open') return` ——
   **一旦选过（active 非空）就再也不会自动选**。处置后 active 仍指向那条已离开列表的问题，于是没有任何切换；
2. 抽屉拿到的 `active` 是一个**快照对象**：处置只做了乐观更新（`setIssues` + 补 `detail`），
   `active` 本身没回填，所以抽屉里 `active.status / assignee / severity / reopenCount` 全是旧值。

## 2. 规则（抽成纯函数，可自检）

`src/renderer/src/lib/selection.ts`：

```ts
nextSelection({ active, list, loading, userFiltered })
→ { kind: 'keep' } | { kind: 'clear' } | { kind: 'select', item }
```

| 情况 | 行为 | 为什么 |
| --- | --- | --- |
| 选中项**还在**可见列表里 | keep | 不打断正在处理的人（例如「全部」页签里改状态，条目仍在列表） |
| 选中项**已离开**视野（处置/归档/合并/被筛掉） | select 列表**第一条**（最前面那条） | 这就是本次要修的场景 |
| 列表为空且原来有选中 | clear（同时清详情） | 不能让右侧继续显示一条不在列表里的问题 |
| 没有选中、且用户自己加了筛选 | keep | 保持原来的克制，避免乱跳 |
| 没有选中、无筛选 | select 第一条 | 首屏默认展开第一条 |
| 正在加载 | keep | 不拿半截数据把选中项清掉 |

配套第二个 effect：**抽屉里的那条问题按 id 从实时列表回填**（`active` 不再当快照用），
并且当它已不在视野里时直接返回 —— 把「推进到下一条」让给上面的规则，避免两个 effect 互相覆盖。

## 3. 同类问题排查（一起修了）

| 位置 | 问题 | 修法 |
| --- | --- | --- |
| 问题监控 · 抽屉 | `active` 是快照，处置/同事回写/重析后详情显示旧值 | 按 id 从实时列表回填（上文第 2 个 effect） |
| 工作台 · 群问题面板 | `expandedId` 指向的那条被处置/归档后仍留着：一旦它以后回到列表（重开/取消归档）会**自己展开**，像「面板乱跳」 | 不在列表里就收起展开态 |
| 增长页 · 素材详情 | 详情那条被删掉或改筛选后已不在列表里，详情仍挂在下面 | 无分页未加载完时，不在列表就关闭详情 |
| 客户页 · 客户抽屉 | 存的是对象快照：列表刷新后显示旧数据；客户消失时抽屉不关 | 改存 id，渲染时从实时列表取（取不到自然关闭） |
| 设置 · 定时任务 / IM 账号 | 正在编辑的实体被删除后，表单仍处于「编辑 xxx」态（保存会报错或误建） | 删除成功且 id 相同 → 退回新建态 |
| 工作台 · 会话列表 | —— | 已正确（删除后自动选下一条），未改 |

## 5. 维护提示

以后凡是「列表 + 右侧详情」的界面，选中状态都按这套规则来：
**只存 id（或让 active 从列表回填），选中项离开视野就切第一条，列表空就清详情。**
规则改动请同时更新 `lib/selection.ts` 与 `scripts/monitor-selection-selftest.mjs`。
