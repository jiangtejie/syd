# 时间显示口径（全应用约定）

> 状态：**已落地（2026-09-12）**。起因：用户要求「时间要精确到时分秒」。

## 1. 约定

**凡是展示「某个时刻」，一律精确到秒**：`HH:mm:ss`，带日期时用 `YYYY-MM-DD HH:mm:ss`。
不再出现只到分钟（`15:20`）或含糊相对时间（`刚刚` / `3 分钟前`）单独承担时间信息的情况。

为什么：
- 排查问题时同一分钟里的两条记录（同步失败、消息、审计）分不出先后；
- 跨设备对照（飞书表格里的时间 vs 本地时间）差一秒就会让人怀疑「是不是没同步」；
- 相对时间过了几分钟就过期，截图/转发出去就不再准确。

## 2. 唯一实现（别各写一份）

`src/shared/monitorMetrics.ts`（主进程与渲染端共用，纯函数，自检覆盖）：

| 函数 | 输出 | 用途 |
| --- | --- | --- |
| `fmtStamp(ts)` | `2026-09-12 15:20:33`（空值 `—`） | 状态、历史、审计、导出、提示词——任何「完整时刻」 |
| `fmtHms(ts)` | `15:20:33`（空值 `—`） | 只需要时间、日期由上下文给出（如消息流里的时间） |
| `fmtTimeShort(ts)` | `今天 15:20:33` / `昨天 15:20:33` / `9月12日 15:20:33`（空值 `—`） | 列表、徽标、抽屉等紧凑场景 |

**不要再用** `toLocaleString` / `toLocaleTimeString` 直接拼时间：各平台与语言包的默认格式不一致
（有的不带秒、有的是 12 小时制），会让同一份数据在不同机器上长得不一样。

## 3. 本轮改到的地方

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 设置页 · 飞书同步状态/历史/证据 | 相对时间「3 分钟前」、`toLocaleString` | `fmtStamp`（含上一轮加的两处「上次同步」） |
| 监控页（徽标/上次分析/议题行）、议题抽屉 | `今天 15:20` | `今天 15:20:33`（共享 `fmtTimeShort`） |
| 工作台 · 群问题面板、渠道文件 | 本地各写一份 `HH:mm` | 删掉重复实现，统一走 `fmtTimeShort` |
| 值班页 · 记录/话术 | `15:20` / `9/12 15:20` | `今天 15:20:33` / `9月12日 15:20:33` |
| 审计与飞书审计/任务面板 | `MM-DD HH:mm`（`withSeconds=false`） | 默认 `MM-DD HH:mm:ss` |
| 日志页、工作台可靠性、报告任务 | 分钟级 | 补秒；「最近运行」= 精确时间（相对时间放括号里） |
| 看板 · 数据新鲜度 | 只有「3 分钟前」 | `2026-09-12 15:20:33（3 分钟前）` |
| 增长页 / 舆情 / AI 工作台 | `toLocaleString` | `fmtStamp` |
| 会话列表 / 气泡 / 时间分隔条（`lib/ui.ts`） | `HH:mm` | `HH:mm:ss`（会话列表的老会话也带时间） |
| 主进程：飞书同步提示、通知文案、导出记录、AI 提示词、值班模板变量 | 分钟级 / 平台默认格式 | 秒级（`fmtStamp` / `fmtHms`） |
| 导出文件名（日志、监控快照） | 到分钟 | 到秒（同一分钟连点两次不再互相覆盖） |

保留相对时间的只有**「年龄/耗时」类**文案（积压 `3 天`、任务 `12s`、报表 `3 天前` 的括号补充），
它们表达的是时长而不是时刻。
