# 营销 AI 工作台 · 工具与生图口径

> 面向：后续接手营销链路的人（含 AI 会话）。
> 定位：**营销侧工具的行为口径与"为什么这么定"的唯一入口**；排期类事项仍看 `docs/improvement-backlog.md`。
> 最后更新：2026-09-19（依据真机实测与线上库核对）。

---

## 0. 一句话

营销侧的图**不是"生成"出来的，是"分工"出来的**：画面交给生图通道，文字交给本地排版；
能不能"高仿原图"，取决于参考图有没有可保持的画面，以及有没有把原图真的发过去。

## 2. 生图：两条路与分流规则

### 2.1 带参考图 = 图生图改写（高仿的主力路径）

传 `referenceAssetId`（原爆款图）→ 走 `/images/edits`，**原图真的发给通道**，
提示词要求"保持构图/机位/光线/版式/文字位置，只换内容与文字"。

真机实测（2026-09-19，通道 `uuapi.net/v1` + `gpt-image-2.5`，原图 + 最强口径提示词）：

| 参考图类型                                  | 版式是否保住                    | 中文文字              |
| ------------------------------------------- | ------------------------------- | --------------------- |
| 照片类（2×2 美食拼贴 + 中间文案带）         | ✅ 结构、构图、文字位置都保住了 | ✅ 逐字准确           |
| 纯文字排版图（白底 20 条清单 / 备忘录截图） | ❌ 被整张重画成美食海报         | ✅ 逐字准确（但没用） |

结论：**能不能高仿，取决于参考图有没有可保持的画面**；纯文字排版图必须走本地排版。

### 2.2 分流：纯文字排版图不交给扩散模型

判据在 `ai/imageText.ts#judgeTextOnlyVisual`（纯函数，有自检）：从视觉拆解的
机位/背景/元素/主体占比里找信号（"无摄影机位/截屏"、"备忘录/导航栏"、"白底"、"清单/表格"、
文字占画面 ≥70%），**至少两条命中**才判 —— 避免把"白底菜品图"误伤。

命中时 `growth_gen_image` 拒绝出图，指向 `growth_make_cover(template='list', items=[…])`。

### 2.3 文字：`textLines` + 回读校对 + 自动补字

- **`textLines`**（最多 6 条，主标题/副标题/角标逐行给全）：逐字进提示词（要求照抄）。
  **只给一句"换成我们店的文案"，模型会自己编字**（实测）。
- **回读校对**：出图后把产物压到 1024 宽、喂回多模态逐字读出来，与 `textLines` 逐行比对
  （标点/空白/全角归一），回执给 `✓ 逐行一致` 或 `⚠ 缺：「…」`。
- **自动补字**：校对发现缺行时，自动用**已生成的那张画面**做底图、本地把缺的行渲染上去，
  作为**同一产出里的额外一张候选图**（`source=local-text`，不覆盖原图）。文字走本地排版，保证完整。

### 2.4 只要画面：`noText`

`growth_gen_image(noText=true)`：提示词与负向词都要求画面里没有任何文字，并留出标题位置；
随后用 `growth_make_cover` 压字 —— 这条路的文字**永不被裁**，代价是版式由模板而非原图决定。

### 2.5 尺寸：按原图长宽比

未在设置里显式填 size 时，图生图按**原图长宽比**出图（长边 ≤1536、取 16 的整数倍）。
平台默认的 1024×1536 会把 3:4 的原图压变形。优先级：设置 size > 原图比例 > 平台默认。

## 3. 图片来源与用途（红线）

`shared/imageSource.ts`（纯函数，两端同一份口径，有自检）：

| source_mark                                           | 判定          | 能当底图/内容依据吗    |
| ----------------------------------------------------- | ------------- | ---------------------- |
| `self:local`                                          | 本店实拍/导入 | ✅                     |
| `gen:image`                                           | AI 生成图     | ✅（对外需注明非实拍） |
| `cover:*`                                             | 本地合成产物  | ✅                     |
| `<平台>:ref` / `:buzz` / `:redownload` / `search:web` | **他人作品**  | ❌ 只能作结构参考      |
| 空/未知                                               | 保守按外部    | ❌                     |

- `growth_make_cover` 的底图**只能**是自家图；传外部图会被拒绝（那是"把标题压在别人的作品上"）。
- `growth_gen_image` 的 `contentAssetId`（"内容以它为准"）**只能**是自家图。
- `referenceAssetId` **可以**是外部图（高仿就是借它的画面与版式），但回执会点名
  "画面来自同行原图，对外发布前自行确认版权" —— 告知而不是替用户拒绝。

## 4. 封面渲染管线（本地）

`cover/templates.ts`（纯函数，有自检）生成自包含 HTML（内联 CSS + data: URI 底图）→
`cover/renderer.ts` 用离屏 BrowserWindow 截图为 PNG。

**两个已修的坑（别改回去）**：

1. **离屏窗口会被系统裁到工作区高度**（1440 屏 → 内容区最多 1392），
   而封面常是 1024×1536 —— 直接 `capturePage()` 会静默截掉底部约 9%（副标题/署名整行消失）。
   现在：先比对窗口实际内容区，被裁就改用 CDP `captureBeyondViewport` 整页截取，
   并做**尺寸自检**（不符即 warn）。回归自检：`npm run test:cover-size`（需 electron）。
2. **清单版式必须走文档流**（flex 列）：标题行数、条目数、署名都不固定，绝对定位会互相压
   （首版实测：角标压住标题末字、列表被 `top:225%` 顶出画布）。

模板：`bold-bottom` / `top-band` / `corner-card` / `plain-center` / `list`（清单榜单）。
清单条目支持 `名称|说明` 两栏（原图常见格式：店名 + 品类/评分），序号由 CSS counter 生成。

## 5. 提示词无关、只能靠机制的三件事（已落地）

1. 长文案比原文案长 → **必被裁**（提示词只能降低概率）→ 回读校对 + 自动本地补字。
2. 纯文字排版图 → 模型会自由发挥 → 按画面事实分流到本地排版。
3. 每次重抽结果不一致（扩散采样随机）→ 多张候选 + 采用流程 + 校对。
