# 议题证据明细同步到多维表格:设计与落地记录

> 状态:**已落地(2026-09-12)**,P0 + P1 全部实现并通过 typecheck / lint / build,映射层有离线自检覆盖。
> 唯一未实测的环节是「关联字段」的字段类型码(见 §7),代码里已做失败退化,不会阻塞同步。
> 前置:议题同步(含写进指定表 / 一键配置)已落地并提交(`86c8280`)。

## 0. 结论(推荐并已采用)

**单开一张「议题证据」子表(一行一条消息),不要把证据塞进议题那一行的单元格**;
议题表可选加一个「关联证据」字段(单向关联),让同事点开议题就能看到证据。

四条理由:
1. Base 单元格文本有长度上限,几十条消息塞一格既看不全也难读;
2. 证据是 **append-only**(消息不可变)→ 天然幂等,子表按 证据ID 映射一次即可,不需冲突处理;
3. 子表可**筛选/排序/分组**(按议题ID、按时间、按来源),一眼看清"这个议题客户到底说了什么";
4. 隐私可控:证据子表可以单独设权限/单独建视图,不必把原文和议题行绑死。

## 2. 三个方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A 单元格内嵌 | 议题行加「证据明细」多行文本列,把 N 条消息拼成一坨 | 零新增表 | 有长度上限、不可筛选、几十条没法读、一眼看不出时间线 | ✗ 不推荐(仅适合极少证据) |
| **B 子表(已采用)** | 新表「议题证据」,一行一条消息 + 议题ID/序号/时间/发送人/内容/类型 | 可分组筛选排序、幂等简单、量放大也不挤、隐私可控 | 多一张表 | ✓ **已实现** |
| C 每议题一篇飞书文档 | 证据导出为文档,议题行放链接 | 长文 + 图片体验最好 | 每议题一次建文档、权限与清理复杂、量大时噪音大 | 后续可选(适合"复杂客诉复盘") |

## 3. 推荐方案(B)详设

### 3.1 子表「议题证据」字段(已实现)

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| 证据ID | 文本 | msg.id | **幂等键**(写入映射用) |
| 议题ID | 文本 | issue.id | 与议题表同名列;不依赖关联字段也能按它分组/筛选 |
| 议题标题 | 文本 | issue.title | 冗余一份,肉眼可读(否则只看到一堆 ID) |
| 客户群 | 文本 | issue.groupName | 便于跨表对照 |
| 序号 | 数字 | 1..N | 该议题内证据顺序(按 seq) |
| 时间 | 日期 | msg_time | 时间线排序 |
| 发送人 | 文本 | sender_name | 昵称,便于读懂谁说的 |
| 来源 | 单选 | is_send / is_team | 客户 / 我方同事 / 我方 |
| 内容 | 文本 | text | 截断(见 3.4)。非文本写 `[图片]`/`[语音]`/`[视频]`/`[表情]`/`[链接/卡片]`/`[名片]`/`[位置]` 占位 |
| 类型 | 单选 | local_type / image_md5 | 文本 / 图片 / 语音 / 视频 / 表情 / 链接-卡片 / 名片 / 位置 |
| 证据图 | 附件 | (P2) | 本地解密后上传,一期先不做 |

> 注意:证据表**只用标准列名**,不套议题表的「列名映射」——这张表是我们自己建的,列名可控;
> 套映射反而会让同事改一个设置就把证据塞错列。

### 3.2 幂等与增量(已实现)

- 映射:kind='evidence', local_id=msg.id → record_id;新增走 `batchCreate`,映射表保证不重复插;
- 增量来源:repo `listEvidenceForSync({sinceMs, limit})`(JOIN issue_feedback 保证议题还在、带 序号/标题/群名);
- 首轮量控制:默认只推**最近 7 天**、每议题最多 **20 条**("首现 1 条 + 最新 19 条"),避免几千行一次灌表;
- 限流:100 条/批 + 120ms 间隔,失败只计入 failed 不中断;
- 删除:议题删除会级联删证据 → 远程行成孤儿。P1 提供「清理孤儿行」按钮:按**本地真实证据 id 集合**比对远程「证据ID」(不能用映射表判断,映射行在议题删除后仍会残留),只删我们自己写入的行,不动同事手填的行。

### 3.3 关联字段(已实现,带退化)

- 议题表加「关联议题」(单向关联 → 议题证据表);建表后尝试创建,失败只记 warn;
- 用的是 REST 数字类型码 `type: 18` + `property.table_id`(对应"单向关联"),与 CLI 指南的 `type=link` + `link_table` 同义;
- **未实测**:本机无法在不落数据的前提下跑一次 dry-run,所以代码把失败当正常分支处理——
  失败时设置页会显示「未建立关联字段(不影响同步):可在证据表按「议题ID」分组查看」;
- 退化路径:用「议题ID」文本列 + Base 视图按 议题ID 分组,功能等价,只多一次点击。

### 3.4 隐私与截断(默认保守,已实现)

- 证据 = 客户原文 → **默认不推**(开关 `推送证据明细（客户原话）` 默认关);
- 打开后仍受三重上限:每条截断(默认 200 字)、每议题条数(默认 20)、范围(默认近 7 天),三个值都在设置页可改(20~2000 字 / 1~200 条 / 1~365 天);
- 非文本证据写占位标记(P2 再做真图附件);
- 设置页写明"客户原话会写入飞书表格,注意敏感信息",并在开关上方显示当前生效的三个上限与"本轮待推 N 条"。

### 3.5 限流与性能(已实现)

- 复用现有 100 条/批 + 120ms 间隔 + 串行;
- 首次全量只推近 7 天,后续按增量推(映射表命中即跳过);
- 同步历史单独记 kind='evidence',设置页历史里显示为「证据明细」,监控页同步 toast 也会报"证据新增 N"。

### 3.6 交互(已实现)

| 位置 | 增加 |
| --- | --- |
| 设置页 → AI 助手 | 新卡片「议题证据明细同步（子表）」:开关 + 三个上限 + 「创建 / 校验证据表」+ 「清理孤儿行」+ 上次结果 + 隐私提示 + Base 视图建议 |
| 设置页 → 同步历史 | kind 显示中文(议题 / 影子回复 / 证据明细 / 拉取同事改动) |
| 监控页 | 同步徽标追加「证据 N 条(待推 M)」;同步 toast 追加"证据新增 N" |
| 设置页 | 「推送聊天原文」改名「影子记录附带更长的聊天原文」并写清它只管影子回复列 |
