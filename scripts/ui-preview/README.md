# UI 预览沙箱（`npm run ui:preview`）

把**真实的渲染端**放进普通浏览器里跑，用假数据看排版与交互 —— 不启动 Electron、不碰本机微信库、
不改用户数据。改营销页/数据页这类「数据驱动的界面」时，用它做前后对比比反复重启应用快得多。

## 用法

```bash
npm run ui:preview     # 构建 → 生成预览页 → 起静态服务（默认 http://127.0.0.1:5199/preview.html）
```

浏览器打开后：左侧导航切页面、页签切屏、列表行可点开详情，全部是真实组件与真实 CSS。
要改假数据（会话、素材、任务、舆情条目）就编辑 `mock.js` 后刷新页面 —— 不需要重新构建。

## 它做了什么（都在 `out/` 里，不动源码）

1. **注入 `window.api` 桩**（`mock.js`）：深度代理，任何未显式覆写的调用回 `{ok:true}`，
   `onXxx(cb)` 返回空取消函数；素材/会话/任务/舆情等关键接口回真形状的假数据。
   同时把图片 `src` 上 `ct-growth://` / `ct-media://` 的请求换成渐变 SVG 占位 ——
   自定义协议在浏览器里加载不了，不换就满屏破图，看不出图墙的排版对不对。
2. **改写演示账号**：渲染端用 `wxid !== 'wxid_demo'` 判断「是否已连接真实账号」，
   不换的话「数据 / 监控」页永远只显示「尚未连接微信」。所以只把对话页初始化里的兜底账号
   换成 `wxid_jiangyanjing`（各页的判据不动）。
3. **生成 `out/renderer/preview.html`**：在真实构建产物上多引一个 `mock.js`。

## 踩过的坑（别重犯）

- **不要给入口 script 加 `?v=` 之类的查询串**：懒加载 chunk 里 import 的是 `./index-xxx.js`，
  加了查询串浏览器会当成另一个模块再加载一份 → 两份 React → 懒加载页报 React #321（invalid hook call）。
  静态服务已经发了 `no-store`，不需要靠查询串破缓存。
- **`keyStore.list()` 必须返回数组**（不是 `{ok:true}`）：设置页会对它调 `.some()`，形状给错直接崩到错误边界。
- **不要用 PowerShell 的 `Get-Content -Raw` + `Set-Content` 批量改带中文的 CSS**：
  中文注释会被按 GBK 解码再写成 UTF-8（满屏「锛?鐨?」乱码，且部分字符不可逆）。批量改就用 Node 读写。
- 预览页是**演示环境**：它证明排版与交互，不代表真实数据下的极端情况（超长标题、上千条列表）。
